## 1. 产品概述

### 1.1 产品定位

**AI中医健康管理平台** —— 基于AI视觉识别技术与中医理论，为用户提供舌诊、面诊、体质分析、健康问答等全方位健康调理建议的智能SaaS平台。

### 1.2 核心价值

| 用户群体 | 核心价值 |
|---------|---------|
| 用户 | 手机拍照即可获取中医健康调理参考，建立个人健康档案，享受个性化健康指导 |
| 推广者 | 通过社交分享获得持续被动收入 |
| 平台 | 通过AI降低中医健康服务门槛，构建用户健康数据资产 |

### 1.3 产品目标

| 目标类型 | 具体目标 | 衡量指标 |
|---------|---------|---------|
| 产品目标 | 上线AI健康分析全功能 | 舌诊+面诊+体质测试+健康问答完整闭环 |
| 商业目标 | 验证付费商业模式 | 付费转化率 ≥ 5% |
| 增长目标 | 建立推广裂变体系 | 推广用户带来 ≥ 30% 新用户 |
| 技术目标 | 支持百万用户架构 | 接口响应 ≤ 500ms，可用性 ≥ 99.9% |

## 4. 使用场景

### 场景1：用户首次使用舌诊

```
用户打开H5页面 → 浏览首页了解功能 → 点击"立即分析" 
→ 授权登录 → 拍照/上传照片 → 确认提交 
→ 等待AI分析（动画） → 显示分析完成 
→ 点击"查看完整报告" → 选择支付方式 → 支付成功 
→ 查看完整报告
```

### 场景2：用户使用面诊功能

```
用户进入面诊页面 → 查看拍摄指引 → 拍摄面部照片
→ 上传照片 → 等待AI分析 → 显示面部特征分析
→ 查看健康建议 → 保存到健康档案
```

### 场景3：用户进行体质测试

```
用户进入体质测试 → 回答问卷题目（约30题）
→ 系统分析体质类型 → 生成体质报告
→ 查看调理建议 → 获取个性化养生方案
```

### 场景4：用户咨询健康问答

```
用户进入健康问答 → 输入健康问题
→ AI实时回答 → 可继续追问 → 保存问答记录
```

### 场景5：用户开通推广员并分享获利

```
用户注册/登录 → 会员中心 → 点击"开通推广员"
→ 立即开通成功 → 获得推广码/海报 
→ 分享到微信群 → 新用户通过推广码注册 
→ 新用户付费查看报告 → 推广员获得佣金 
→ 推广员申请提现 → 平台审核 → 打款到微信
```

### 场景6：用户复购

```
用户再次打开 → 进入会员中心 → 查看剩余次数 
→ 购买次数包/会员 → 支付成功 → 继续享受服务
```

- [ ] 跳转至首页

## 7. 功能边界

### 7.1 MVP包含

#### 核心功能
- 手机号+验证码注册登录
- 微信授权登录（H5）
- AI舌诊分析（拍照+AI分析+付费查看）
- AI面诊分析（拍照+AI分析+付费查看）
- 体质测试（问卷+AI分析+付费查看）
- AI健康问答（基础版）
- 微信支付+支付宝支付
- 健康档案（历史记录）
- 推广码生成+佣金统计
- 后台用户/订单/AI/推广管理

#### 前端特性
- 移动端H5自适应布局
- 响应式设计，适配各种手机屏幕
- 微信小程序风格UI
- 图片压缩上传
- 流畅的动画效果

### 7.2 MVP不包含

- 会员自动续费
- 优惠券系统
- CMS内容系统完整版
- 医生合作功能
- 商城系统
- 视频问诊
- 中药配送
- 多语言支持

## 11. 风险分析

| 风险类型 | 风险描述 | 影响 | 概率 | 应对措施 |
|---------|---------|------|------|---------|
| 合规风险 | AI健康建议被认定为医疗行为 | 高 | 中 | 添加免责声明，避免诊断性用语 |
| 技术风险 | AI识别准确率不足 | 高 | 中 | 多模型融合，持续优化Prompt |
| 市场风险 | 用户不愿为AI分析付费 | 高 | 中 | 免费体验+付费查看模式 |
| 成本风险 | AI调用成本过高 | 中 | 中 | 图片压缩、结果缓存、成本控制 |
| 竞争风险 | 大厂推出类似产品 | 中 | 低 | 快速迭代，建立用户粘性 |
| 推广风险 | 多级分销被认定为传销 | 高 | 低 | 只做一级返佣，合规纳税 |
| 支付风险 | 支付通道被封 | 高 | 低 | 多支付通道备份 |
| 数据风险 | 用户健康数据泄露 | 高 | 低 | 加密存储、访问控制、审计日志 |
| 内容风险 | AI回答出现错误医疗建议 | 高 | 中 | 建立内容审核机制，设置回答边界 |
